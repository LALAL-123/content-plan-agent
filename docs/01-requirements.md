# 01 需求

## 用户

运营人员。要为一个主题在给定预算和截止时间内拿出可执行的内容活动方案。

## 目标

| 输出字段 | 含义 |
|---|---|
| `plan` | 所选制作方式、脚本 ID、素材 ID、方案 ID |
| `steps` | 四个步骤（素材检索、成本估算、脚本撰写、方案保存）的实际状态：done / reused / failed / not_run |
| `tool_results` | 各方式的估算结果、脚本内容 |
| `total_cost` / `budget` | 所选方式的估算费用与预算 |
| `saved` / `deduplicated` | 是否已保存、是否为重复执行去重 |
| `task_status` | completed / needs_input / infeasible / failed_partial / incomplete |
| `gaps` | 未完成原因或缺口（如“最接近的 P-C：预算缺口 1”） |

## 输入

```json
{"request_id": "PLAN-C03", "topic": "冬季露营", "budget": 10,
 "deadline": "2026-11-08 18:00", "preferred_option": "P-A"}
```

材料：`data/materials.json`（合成素材库）、`data/cost_table.json`（固定步骤与三种制作方式的费用、耗时，“当前时间”固定为 2026-11-03 09:00 以保证可复现）。

| 方式 | 总费用 | 总耗时 |
|---|---|---|
| P-A 达人合拍 + 精剪 | 12 | 51h |
| P-B 自制口播 + 模板剪辑 | 8 | 23h |
| P-C 图文轮播 | 5 | 9h |

## 范围

做：缺约束追问、按约束选方案与重规划、工具失败的重试/替代、保留成功步骤、续跑、防重复保存、上限停止。

不做：真实投放、多方式组合优化、多人协作、界面。

## 成功标准

1. 五个必须验收点（正常完成、缺预算或截止时间、工具失败、预算超限、重复执行）各有用例且检查全部通过；加分项“失败步骤续跑”有用例。
2. 关键缺陷为零：
   - 失败步骤不得记为 done；
   - `total_cost` 等于所选方式的估算值，且不超预算；
   - 未保存成功不得 `saved=true`；
   - 缺预算或截止时间时不猜测、不保存。
3. 同一请求执行两次只有一份方案，第二次不重做已成功步骤。
4. 达到步数或调用上限时返回 `incomplete`，并带上已成功步骤。
5. 至少两条执行路径体现重规划：预算充足用 P-A（c01）vs 超预算改 P-B（c03）；截止时间紧改 P-C（c08）。
