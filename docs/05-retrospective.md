# 05 复盘

> 初稿，按本人实际体会修改。

## 最难的问题

**“保留已成功步骤”放在哪里。** 如果让模型在 finish 里自报步骤状态，模型可能把失败步骤写成 done，也无法跨两次执行保留结果。最后由工具在成功时写任务台账，失败调用不写；`finish` 后护栏用本轮记录和台账重算每一步状态。这样同一台账同时支撑三件事：失败处理如实、续跑只补做缺失步骤、重复执行不重复保存。

**重规划要让模型“看得见”。** 估算工具直接返回 `within_budget`、`within_deadline` 和缺口，制作方式列表不带费用，模型必须估算后才能比较；脚本失败的替代方案做成显式工具 `get_script_template`，而不是在工具内部自动降级。这样“换方案”是模型的一个可追踪动作，Trace 里能看到为什么换。

**检查不能绑定执行路径。** 真实模型可能先写脚本再估算，也可能一次估算全部方式。验收检查只看最终结果、工具事实和台账；只有“偏好方案优先”“重复执行不重做”这类体现业务要求的行为才作为路径相关的检查。

## 学习收获

- 状态是 Agent 失败处理的前提：没有状态只能证明串行调用，有了按请求建键的台账才谈得上续跑和幂等。
- 工具返回的信息量决定模型能否重规划：给出“是否满足约束 + 缺口”比只给原始数字更可靠。
- 用例要成对设计：同一主题只改预算或截止时间，看所选方案是否随之变化。
- 工具返回什么，弱模型就用什么：第 1 轮续跑时模型读了台账就直接结束；`get_task_state` 加上 `pending_steps` 后，第 2 轮起续跑能补做脚本并保存。但“不要重做”这类只写在提示词里的要求，模型仍不遵守（c07），要落到工具上。
